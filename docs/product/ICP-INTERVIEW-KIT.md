Status: **QUESTION SET FINAL (Commander revision 2026-10-24) — 0/10
interviews conducted.** This revision exists so the first question tests
the REAL thing — whether "done" is a real, frequent, expensive problem —
instead of leading the witness toward our own moving-goalposts
hypothesis.

## The questions (FINAL — do not improve mid-run)

```text
Q1（开放式起点 — 不带假设）:
  最近一次你让 AI、外包或别人完成一项开发工作，
  最后你怎么判断它到底算不算完成？

追问（只追事实，不替对方命名问题）:
  有没有出现过对方觉得完成了，但你认为还没完成？
  当时差在哪里，最后怎么解决，付出了什么成本？

  （继续顺着具体案例问下去，直到对方自己讲出标准模糊 /
  事后加要求 / 返工 / 验收争议 —— 不要替他说出这些词。）

Q2（机制意愿 — 仅在案例谈透之后）:
  如果开工前能把其中可机器判断的部分先锁死，
  交付后只按这套规则判断，
  你愿不愿意把满足这部分直接认定为已完成？
```

## Why this version is stronger — every outcome is real evidence

```text
NO PAIN              "我们几乎没有完成争议"          → 真实负证据
PAIN / MECHANISM NO  "确实很痛，但我必须保留最终判断权"  → 定价与定位证据
PAIN / MECHANISM YES "事前写清的部分，我愿意锁死"       → 真正的 ICP
```

The third type is who EXPERIMENT-001's next target comes from.

## Demo discipline (PRODUCT-UX-R2 is persuasive — that is the risk)

```text
先谈过去真实案例 → 确认痛点 → 问 Frozen Outcome 机制意愿
→ 只有愿意的人 → 再给他看当前产品
→ 观察他是否真的愿意拿一项工作来试
```

The frontend is NOT shown before Q1/Q2 are answered. Showing it early
pollutes the interview: the subject starts evaluating the product
instead of exposing how they actually work. The "willing to bring one
real task" observation IS the bridge into P2 (EXPERIMENT-002, ECONOMIC
ACCEPTANCE).

## Rules of engagement

- 不先讲 Intent。不提区块链、协议、证明架构。
- Q2 之前不展示任何产品/文档/截图（本节 Demo discipline 的硬红线）。
- 对方的原话当场记录（或录音后逐字誊录），不转述、不概括。
- "没遇到这个问题" = 有效数据（NO PAIN），不是失败。
- 每次访谈一条记录，追加式（不修改历史记录）。
